Decision record 0002 · not student-facing

The Shortest Route

A website a learner can edit from the Claude app — whether it needs a repository, and whether an agent maintaining documentation can spare them from learning git. A decision addressed to the author, not a sheet to hand anyone.

Revised 2026-08-30, same day, and the first version was wrong about the first question. It said a repository is required. That is true of Claude Code on the web and it is not true of the Claude app, because Cowork connects a real folder with no repository and no terminal. The wrong version is not edited away: its decision record is kept below, superseded rather than corrected, which is the rule this course teaches for exactly this case.

The defect is the one this course is about. The first answer was assembled from the surface its author already knew, and read as a fact about the whole product. Nothing in it was unchecked — the quotes were real and are still on the page. They were quotes about a different route.

Assembled by extraction, then partly walked. Every claim comes from cold-start.html, search-to-shipped.html, four-barriers.html, points.md or the vendors' own current documentation, cited in place. On 2026-08-30 route C was walked as far as a path with no GUI can go: three of its seven checks came back confirmed, one came back NOT DONE, and three could not be reached. Which is which is in §7, and no row is left to look like another. Never murderboarded.

This is a decision record, not a handout, and it moved folders to say so. It was first filed in docs/handouts/, whose own front door defines that folder as “things a learner is handed.” This is a memo to one person weighing one choice. Nothing on it is ready to be handed to anybody, and it is deliberately not in tools/pages.txt or the build.

The two questions, as asked. Is a repo necessary? — and can the agent maintain sufficient docs to avoid having to teach a noob git?

Answers: no, and no. A repository is not necessary — Cowork removes the requirement. It is still worth buying, and the price is one free account. What it buys is two specific things, both nameable, both already documented failures in this course's material. And documentation cannot replace the teaching, because on the shorter route there is more to hold, not less.

Why this recommends a road that has been half-walked at most, and says so instead of hiding it. §7 added evidence for route C on 2026-08-30. Route B has still never been run by anyone here, so the asymmetry below is what the recommendation rests on, not a comparison of results.

1 · The author does not use Cowork, and that is not evidence about a learner. Recorded in his own words, 2026-08-30: “i don't use cowork so i'm reluctant to include it. my work is too chaotic for the claude app alone. that should not propagate to all users.” That describes one working style — many concurrent sessions, several machines, a dozen repositories — and it is a fact about the author, not about the route. A learner with one laptop and one project has none of those conditions. It is written down here so it cannot quietly become the reasoning, which is what an unexamined preference does.

2 · The two costs charged against Cowork below are vendor-documented, not preferences. Desktop-only with no cloud copy, and a manual re-upload to publish. Those are quoted in §2 and would still be true if the author used Cowork daily. Everything else about it is untested here, and nothing on this page claims Cowork is worse at the job it does.

3 · The default is chosen on asymmetry, not on a result. Neither road has been walked and there is no time to walk one. So the tie is broken on what each mistake costs. Wrong about the repository: a learner who never needed a second machine paid one free account and about ten minutes. Wrong about Cowork: a learner who did need one has their only copy on a laptop, and finds out on the day the laptop is gone. The first is a refundable ten minutes; the second is not refundable at all. That is a reason to default, and a default is a weaker thing than a finding. This page claims only the weaker thing.

4 · The exclusion carries its own release condition, so it does not become permanent by inertia. See the fifteen-minute test in §7 — it is the whole of what would settle this, and it needs no learner and no course.

1 · Four routes, and what each one actually is

the field

“Edit it in the Claude app” describes four different products with four different requirements. They are not variants of one thing, and only two of them end with a file the learner owns at an address they control.

RouteRepoTerminalEdit from
the Claude app		 Survives the
laptop		How it publishes
A · Artifact nonenoneyes n/a Automatic. But it is a page in somebody else's system, not a file you keep.
B · Cowork on a folder nonenoneyes no Drag the folder to Cloudflare, every time. A step someone must remember.
C · Claude Code on the web requirednoneyes yes Automatic on push. Nobody remembers anything.
D · Folder → wrangler nonerequiredno no A typed command. The terminal is the thing being avoided.

Route A is not a straw man — this course runs on it. All four handouts, this one included, are published as artifacts and read that way. It is a real channel. What it cannot do is be the learner's, at their own address, with a copy they keep.

Route D is Cold Start 7.3, and it is here to be ruled out. 7.3 calls it “the road most people should take, and it is three steps shorter.” That is true, and it is true only with a terminal — it needs wrangler. Take the shell away and the ranking inverts: the shortest road becomes unreachable. See §5.

So the real decision is B against C. Both are defensible, which is what makes it a decision rather than a step — and only one of the two has been used by anyone here. The table above is a field, not a scorecard: it says what each route requires, and it does not say which is better at the job it does.

2 · Is a repo necessary? No. Is it worth buying? Yes — at a stated price

question one

Cowork gives Claude a real folder on the learner's disk, from inside the Claude app, with no repository and no terminal. That is the whole of route B, and it is the shortest route to a website the learner owns:

Direct local file access: On desktop, Claude can read from and write to your local files without manual uploads or downloads. Get started with Claude Cowork

It runs code and shell commands in an isolated environment on Anthropic's servers, and it is on the same paid tiers as the alternative — “Pro, Max, Team, Enterprise” — so the plan is not what separates the two routes. Nothing forces a repository. The first version of this page said otherwise, and was quoting the requirements of route C.

What the repository costs

One free account, created in a browser in four minutes. Cold Start 1.1 already asks for it on independent grounds, and already calls it the step people skip. Nothing else changes: on route C the learner still types no git commands, because Claude commits and pushes.

What it buys, and both are things this course has already watched fail

One: a second place to exist. A Cowork project lives on one laptop and does not leave it. Web and mobile sessions reach the folder only while that desktop app is running, and project data has no cloud copy at all:

A cloud session can read and write files in folders you've connected on your computer only while the desktop app is open on that computer. … Projects are desktop-only and stored locally, with no cloud sync for project data at this time. Use Claude Cowork on web, desktop, and mobile

Cold Start named this failure before Cowork existed, and named it as the reason the account is not optional:

Without it, everything you and the agent make lives in one folder on one laptop: it reaches no other machine, no collaborator, and no future session — and none of that announces itself. The day it matters, it is already too late to have done this. Cold Start 1.1

Two: the publish stops being a step someone remembers. Route B's only browser-only publish is Cloudflare's drag-and-drop, and it is a fresh upload every time — “select Create a new deployment to begin a new version of your site,” then drag the folder again. Route C's repository connection redeploys on every push, with nobody doing anything. Put on this course's own table, that is the difference between tier two and tier four, and §3 is about why that gap is larger than it looks.

So the honest statement. Route B is shorter and it is not wrong. It is the right answer for a learner who will work on one machine, alone, on something they could rebuild in an afternoon — and a course that told that learner they must have a GitHub account would be wrong. Route C costs one free account and buys the two things whose absence does not announce itself. That is the trade, and it is now a choice rather than a requirement.

What this page will not claim. That route B is worse. Nobody here has run it. The two costs above are real and sourced; whether they matter to a given learner is a question about that learner, and this course has not asked one.

3 · Can documentation replace teaching git? No — and this course already says why

question two

The proposal is that the agent keeps the docs good enough that the learner never has to understand what is underneath. That is a fix, and this course has a table for grading fixes:

TierWhat it isWhat it costs to ignore
ProseA rule written in an instructions fileNothing. It is skipped silently.
ChecklistA step someone must rememberNothing, when they are busy.
TestSomething that fails loudlyA red line. Cheap and visible.
StructureThe wrong thing is not reachableIt cannot be ignored.

“Agent-maintained docs” is tier one. It is the most available fix and the weakest, which is exactly the pairing the course's own worst incident is about:

Writing a sentence costs nothing, takes five seconds, feels like having solved something, and produces an artifact you can point at. Every stronger fix costs more and looks like less. The weakest mechanism is the most available one, and availability beats effectiveness unless something forces the issue. docs/cases/2026-08-28-the-weakest-fix-is-the-most-available.md

And documentation has a second defect the table does not show: it rots without saying so. Search to Shipped names it as one of six things that will bite you —

Staleness. Documentation was true when written and says nothing about the difference. Including official pages, including yours, including what you told the agent to remember last month. Search to Shipped, Phase 6

This page is its own instance. The first version was documentation, written carefully from real quotes, and it was wrong within the hour because it described a product surface rather than the product. Nothing warned anyone. A reader had to know something it did not.

The exception, which is the part worth keeping

The material carves out one kind of document that does hold, and states precisely why:

A project instructions file is an instruction to behave — it competes with everything the model already believes, and it loses. A glossary is not an instruction. It is the fact the session reasons from. A rule asks the model to override a prior; a definition replaces the prior. That is why one holds and the other does not. It Looked Right, challenge 4

That is the answer, split in two. Docs written as rules for the learner (“always publish after you edit”) are tier one and will be skipped. Docs written as definitions — this word means this state — are the exception, and they are exactly what a beginner is missing. Claude can maintain the glossary. It cannot maintain the discipline.

4 · What the learner actually has to know, which is not git

the finding

On both live routes the learner types no git commands. So the teaching burden is not a command set — it is four states, and the gap between each pair of them. Every one is a fact, not a habit, which puts them in the exception carved out above.

StateMeansThe gap under it B · CoworkC · repo
Written The file on the disk changed. Nothing is recorded. Nothing can be undone, and nothing says why. openopen
Committed The change is in the record, with a reason attached. Committing is not pushing. An unpushed commit exists on exactly one machine and reaches nobody, including you tomorrow on a different one. no such stateopen
Pushed It is on GitHub. A second machine, and Claude, can see it. Pushed is not published. The visitor still gets yesterday's page. no such stateclosed
Deployed The address serves the new bytes. The only one a reader can observe, and the last to happen. manualautomatic

Read the last two columns before concluding that route B is simpler. B has fewer states but leaves the observable one in a human's hands forever; C has more states and closes the two that have actually caught people. Fewer concepts is not the same as fewer ways to be wrong — B's single remaining gap is the one that decides what a visitor sees.

Both of C's gaps are documented failures in this estate, which is why they are the ones on the list. Committed-not-pushed is Search to Shipped step 12, written after “a night's work that reached the next morning as nothing at all.” Pushed-not-deployed happened during the writing of this page: the session board records a rebuilt page sitting correct in the repository while “the live page's description says 30 until someone runs npx wrangler deploy.” Two states, both already proven to catch people who do know git.

What this costs against the course's stated git scope

The outline fixes the git scope at three commands — commit, diff, log — and says explicitly: no branches, no remotes, no merge. points.md already records that this does not survive contact with step 0:

D1 pre-empts §6. If a GitHub account is step 0, a remote exists from the first hour, and §6's “commit, diff, log — no remotes” is already contradicted at the door. points.md §D

Neither route opens that tension; both close it in the cheap direction. The scope stops being a list of commands the learner runs and becomes a list of states they can check — and diff survives unchanged, because reading a diff for scope is one of the four checks that need no code. The learner reads; the agent types.

5 · The route, and where it forks

one evening

Steps 1 and 2 are shared. The fork is step 3, and it is the decision recorded in §6. Every step ends with a condition you can check — because an action and its report are two different events.

  1. 1

    Get a paid Claude plan, and find out which kind it is.

    Both routes need one: Cowork is “available on paid plans (Pro, Max, Team, Enterprise)” and Claude Code on the web is in research preview for Pro, Max and Team. A free account opens neither door. Read What It Costs first: a personal plan is an allowance you hit and stop; an institutional billing code is usually uncapped, and nothing stops or warns.

    Done when you can sign in, and you can say what happens when you use too much — it stops, or it bills.

  2. 2

    Say the whole thing in one sentence.

    “A web page that shows my recordings one at a time and lets me mark the bad ones.” If you cannot say it in a sentence, you are not ready to ask for it. Then break it into parts, and plan to do one element, never two. This costs nothing and is the same on both roads.

    Done when someone outside your field understands what it does, and every item on your list is one afternoon or less.

  3. 3

    Fork: connect a folder, or make a repository.

    Route B — Cowork. In the Claude desktop app, make a project and connect a folder. Nothing is installed, nothing is created anywhere else. If a session later reports no connected folders, check File → Settings → Cowork → “Run new tasks in the cloud” — with that on, tasks run in the cloud and cannot reach local files.

    Route C — repository. On github.com: New repository → tick Add a README → Create. That tick is what makes it a repository with something in it, which is what a cloud session needs to clone. Keep it private. Then at claude.ai/code, connect the GitHub account and pick it. No git init, no terminal.

    Done when Claude names a file that is actually in your folder — or, on C, when the repository is visible on github.com and in the picker at claude.ai/code.

  4. 4

    Do one element. Review the diff for scope, not correctness.

    What did it touch that you did not ask about? Then run it and look, list the files that now exist, and open the artifact yourself. None of those four checks needs you to read code. On route C, let Claude commit and push when you are satisfied.

    Done when you have seen the thing work — not read a message saying it does — and can name in one line the single change that just happened.

  5. 5

    Publish, and notice which kind of publishing you bought.

    Route B. Cloudflare dashboard → create a Pages project → drag the folder in. Browser only, no repository. Limits worth knowing: a zip or a single folder, 1,000 files, 25 MiB each — ample for a website. Every later change means dragging it in again.

    Route C. Cloudflare dashboard → connect the GitHub repository. Private repositories are supported and the setup is in the browser. From then on every push redeploys and nobody has to remember anything. The alternative is GitHub Pages, also browser-only, but on the free plan it serves from public repositories only — and private is the right default for research. That trade is Cold Start 7.3's, restated.

    Done when the URL loads on your phone, off your wifi — and then again after the next change, which on route C means without you doing anything.

Step 5 is the whole decision in one step. Route C's auto-deploy is the only tier-four element available on either road — the wrong thing is not reachable. Everything else on this page is prose. It is bought once, in a browser, in about ten minutes, and it is what the free account was actually for.

What we chose

A GitHub repository as the substrate, on the grounds that the Claude app cannot edit a project without one.

Why it was wrong

The premise was false and the evidence for it was real. Claude Code on the web does require GitHub, and the quotes saying so are still on this page and still accurate. But Cowork connects a local folder from the same app with no repository, so the requirement was never the product's — it was one surface of it.

The record was weaker for it. It listed artifacts and folder-plus-wrangler as the rejected options; neither is a serious rival. It rejected nothing that could have won, which is the tell that a decision was not actually made.

decisions/0002-buy-the-repository-rather-than-require-it.md
Date: 2026-08-30  ·  Status: proposed  ·  Supersedes 0001

What we chose

A GitHub repository, created in a browser, with Claude Code on the web as the editing surface and Cloudflare Pages on push as the publishing mechanism.

What we rejected

Cowork on a connected folder — no repository, no terminal, real files the learner owns, and genuinely the shortest road. This is the option that could have won. Set aside rather than beaten. Two documented costs count against it: the project is desktop-only with no cloud copy, so it reaches no second machine, no collaborator and no session started anywhere else; and its only browser publish is a manual re-upload, which leaves the one state a visitor can observe in a human's hands forever. Nobody here has used it, so those are the only two things known about it, and neither is a judgement of how well it does its job.

Artifacts alone — shortest of all, and the learner ends with no file they own and no address of their own.

Cloudflare from a folder (Cold Start 7.3) — shorter if there is a terminal. There is not one.

Why

Not for version control, and not because anything forces it. One free account buys two things whose absence does not announce itself — a second place for the work to exist, and a deploy that happens without anyone remembering. Both are failures this course has already recorded happening to people who knew better.

And because the two mistakes cost different amounts. Neither road has been walked. Choosing the repository and being wrong costs a learner ten refundable minutes; choosing the folder and being wrong costs them the work. This is a default broken on asymmetry, not a result — recorded as such so that nobody later cites it as evidence it is not.

What it costs

One free account and about ten minutes. No git commands are taught — four states are, and two of the four have already caught people in this estate who do know git.

Revisit if

The fifteen-minute test in §7 comes back the other way. That is the cheapest thing that could overturn this and it is the first thing to do when there is time.

Or Cowork projects gain a cloud copy, or reach a second machine — the first cost goes. Or Cowork can reliably drive the GitHub connector to commit and push on the learner's behalf, in which case route B acquires route C's durability without route C's setup and this record is superseded again. Or the learner's institution mandates a non-GitHub host, in which case cloud sessions become bundle-only and route C does not survive.

Or somebody teaches a learner and watches. Everything above is reasoning from documents. One person on one laptop, observed for an hour, outranks all of it.

What the walk actually bought. Three of seven rows are green, one of them on a human's say-so and two on a machine's. It did not confirm the route. It confirmed that the machine-checkable half does what the page says, and it turned the unexamined half into a named list — which is the smaller claim, and the true one.

And it turned up one thing worth more than the confirmations. Step 3's two halves are not one step. Linking the GitHub account to Claude happens once, inside the app, and is what the author had already done. Creating the repository happens on github.com and is a different action on a different site — “To start a new project, create an empty repository on GitHub first.” This page had collapsed the two, which made a done thing look undone and a two-site errand look like one.

⚠ An untested risk this walk introduced rather than removed. The repository here was created with a README, so it had a commit to clone. The documentation says to create an empty repository, and an empty repository has no commits and no branch. Whether a cloud session can clone one is untested — and it is the difference between a learner's first action working and failing with a message they cannot read. Step 3 says tick Add a README for exactly this reason; that instruction is now load-bearing and is still a guess.
