Each one is a shell script or a hook written after a specific failure, and each carries the date of that failure in its own header — so this table is transcribed from the tools rather than reconstructed from memory. The name is borrowed from sapper, which describes its own job as sweeping for known mines before they ship.

no-heredoc-source.sh7 repos · hook

Shell heredocs mangle string escapes on the way to disk, and the result still looks right in a diff. Two MATLAB files in one session: \r read as a carriage return, \n became a literal newline that terminated a string early, the script stopped parsing, and every figure silently failed. The gate refuses to write source through a heredoc at all.

Costs: use the file tools instead.

What the spread column means, and why it is the interesting one. An instrument in seven repositories was worth carrying six times. The four that travelled — a session briefing, a heredoc gate, a freshness check and a roster check — are not the clever ones; they are the ones that fire without being remembered. Every instrument that stayed in one repository requires somebody to invoke it. That is the whole finding of the table, and it was not designed in: it is what the counts came back saying.

Method. Counted 2026-09-01 across eighteen local repositories with find, git rev-list and git branch --no-merged. Origin failures are quoted or condensed from each tool’s own header comment, which is where this estate records them; nothing here is reconstructed from memory. Duplicate hits from -worktrees checkouts are collapsed, so a count is repositories rather than working copies.

The thirty days is a first-appearance date, and that is not the same as an authorship date. Every one of the twenty entered git between 2026-08-01 and 2026-08-30, measured with git log --diff-filter=A. For a vendored tool that date is when the copy arrived in that repository, so four of them are older upstream than they look here. The window is real; the attribution inside it is approximate, and this sentence is the correction that would otherwise have to be made later.

What was excluded, and the criterion. One repository carries ninety files under tools/; most are analysis and figure scripts (make_*_figure.py, probe_*.py) and are not instruments in this sense. The line drawn here is: does it check, gate, coordinate or retrieve? Analysis code that produces a result is out; a script whose whole job is to notice something is in. That criterion is a judgement and a different one would change the count of twenty.

Not verified. These headers were read, not run. No selftest was executed for this table, and mutation_check.sh exists precisely because a green selftest has already turned out to prove nothing here. The dates are as each tool states them, and a tool that misdates its own origin would carry the error straight into this table uncorrected.

Also not shown: what any of it failed to catch. Unmerged branches across these repositories run from 14% to 88%, and no instrument in this table addresses branch hygiene. A ledger of cleared mines is not a map of the field.
