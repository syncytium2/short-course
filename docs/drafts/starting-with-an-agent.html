The Cheap Window

Starting someone on coding agents — sequenced by dependency rather than by topic, branching on four questions asked at the door, and deferring every guard until something has gone wrong to justify it.

The window, and what closes it

There is a short period, once, when all of this is free. It runs from the moment you decide to work this way to the moment you have a real project with real files in it. After that you are retrofitting — writing a path helper around scripts that already hardcode paths, adding a remote to a repo with ninety commits in it, deciding which storage holds what after the disk has filled.

Nothing announces its closing, and everybody gets exactly one.

Most of what follows is cheap now and merely expensive later. Two items are different: they are impossible late.

A commit stamp recording that an agent wrote something cannot be applied backwards. Add it on day sixty and every earlier commit is permanently ambiguous about who wrote it — a repo in this estate has to say assume agent authorship unless a commit says otherwise for everything before the day it added one. A version or first-published date works the same way: it is derived once from the record, or it is typed by hand forever after, and a typed date is a second source that goes stale silently.

That asymmetry is the whole argument for doing this at the start rather than when it hurts.

Four questions at the door

Asked first, because the answers decide how much of the sequence applies. Answering them in week three means discovering them, which costs more.

  • A One machine, or more than one? One machine drops most of the storage and continuity work below. Two or more, and a shared remote stops being optional — machines share a repo through a remote or they do not share it at all.
  • B Alone, or with other people? Working alone, a repo is a record for your future self. With others, it is also a message, and branches, pull requests and review enter the picture.
  • C Who pays — and is there a ceiling? This is the question people skip and it is the one that bites. See the money section below; the answer changes what can go wrong, not just what it costs.
  • D Do you need large storage or a cluster at all? Most people need neither. A laptop, synced storage and one repo covers the majority of this work. Knowing which side of that line you are on is the decision — and if you do need them, start asking now, because other people have to approve it.

Chat is not an agent

The distinction this course exists to teach is one that institutions already enforce at the level of who gets an account — which makes it free evidence, and evidence that cannot be accused of being staged.

U-M GPT all active students, faculty and staff, three campuses and Michigan Medicine — free, capped at 75 prompts an hour No — a chat box
U-M Maizey same population, but requires a billing code and ownership of a group No — a chat box over your own documents

The most useful fact here is not logistical. The institution gives everybody a chat box for free and puts everything past it behind a billing code. The escalation the first exercise demonstrates is one the university has already built into its own sign-up flow.

The beginner's page never names an agent

The Getting Started page walks a newcomer through three services in order — chat box, chat box over your own documents, gateway — and does not name a single agent. The closest it comes is calling the Toolkit suitable for those who "require full control over their AI environments and models." Someone who follows the official on-ramp end to end arrives at a chat window, having been told that is what this is.

One link away, the Toolkit's own page names them: Claude Code, Codex, and Codex for the Classroom, as keys you generate in the portal. And in the same breath it says who it thinks you are:

"U-M GPT Toolkit is intended to provide Developers with access to our AI Services API gateway… it is assumed that Developers who are granted access to the API gateway already have API experience and technical expertise."

That sentence is the gap, written by the institution. The agent is not hidden and it is not hard to get — it is one self-service form behind a door labelled for developers, and we assume you already know this. Everyone who does not recognise themselves in that description stops at the chat box, which is exactly where the on-ramp left them.

The rules this runs on

Stated first, so the sequence reads as consequences rather than as tips. These are simultaneous constraints, not stages.

  • One thing at a time. One change, verify, commit, next. You cannot tell what broke if you changed four things.
  • Spec, validate, re-spec — and re-spec is the normal case. Not the exception, not a sign of a bad prompt. Someone who never re-specs is accepting first output.
  • Guards are built only from friction. Every guard worth having exists because something specific went wrong first. Building them up front is the asymptote with extra steps.
  • A request is not a rule. An instructions file is not enforceable. Use all the bad words you like; the second sentence is still skipped.
  • The repo is a record, not undo. What happened and why — including what did not work, which stays in the history rather than being edited away.

The sequence

Ordered by dependency: each layer can only be verified once the one below it exists. One thing runs the other way — anything involving people who are not you takes longest, so it starts first and finishes last.

A Access minutes, or weeks — depending on question C
  1. 1 Pick a route, and find out whether it has a ceiling. A personal plan is bought in minutes and the plan is the ceiling. An institutional route usually needs a departmental billing code, and getting one takes days to weeks because somebody else approves it. Issuing the key afterwards is self-service and quick. Everything in phases B and C proceeds while the code pends.
  2. 2 Set the spending quota at the moment you create the key. Not later, not after the first statement. The portal offers the field and nothing prompts you to use it; a ceiling you have to remember to build is the one you will not have. Whether a billing code is available to you at all is usually an unasked question rather than an ineligibility — ask early, because that part is the slow part.
B Identity, before any code exists hours
  1. 3 A code-hosting account, an SSH key, and a logged-in command line tool. Doing this now is what makes step 10 a single sitting instead of a migration.
  2. 4 Whatever else your institution requires: login, VPN, synced-storage client.
C Machine baseline one sitting
  1. 5 A package manager, then the handful of tools everything else assumes. Version control, the hosting CLI, a JavaScript runtime, a fast search tool, a JSON reader. Agents reach for these constantly and fail oddly when they are missing.
  2. 6 An editor and the agent itself.
  3. 7 One language runtime. Only the ones you need. Most people need one.
  4. 8 Stop the machine sleeping through its own work. A session or an analysis run that outlasts your attention dies when the lid closes, and it dies without a result. On a Mac caffeinate -dimsu is built in and needs no install; Windows has PowerToys Awake, Linux has systemd-inhibit. A good share of the people who think they need a cluster need this instead — try it before filing a request that takes weeks.
D Decisions that are free now before the first real project
  1. 9 Write down which storage holds what. Three sentences. It prevents both failures at once: large outputs strangling a sync client, and small shareable results stranded where the other machine cannot see them. Write it before the first data file exists, not when a disk fills.
  2. 10 Write the path helper before anything hardcodes a path. Cheap now, archaeology later. A sibling project carries a stale path island it describes in its own words as rooted somewhere nothing else uses — flagged for cleanup, still not fixed.
  3. 11 Start the repo and add its remote in the same sitting.
  4. 12 Ignore data by extension; pin line endings on shell scripts. A carriage return in the first line of a script is a bad interpreter failure on a Linux machine, and it is a genuinely awful thing to debug from a Windows checkout.
  5. 13 Stamp agent authorship on commits, automatically. One of the two items that is impossible late rather than expensive. Everything committed before the stamp exists is permanently ambiguous about who wrote it.
E First contact, which contains a deliberate failure first week of real work
  1. 14 The bake-off: the same request to a search engine, to a chat box, and to the agent. Shows the escalation instead of asserting it. Search returns links and you do the work; chat returns text and you decide what to do with it; the agent acts on your filesystem. It starts from the one tool everybody has already used, and it opens with the machine being wrong rather than with reassurance. Failure is the first move, not the caveat.
  2. 15 One real task from your own work, small, with the check named before it runs. Four checks that need no code: read the diff for scope rather than correctness, run it and look, list the files that now exist, open the artifact yourself. Name which one applies in advance, or it will not happen — everything can look right and be totally wrong.
F The guard layer deliberately empty
  1. 16 Nothing. On purpose. No hooks, no session-start briefing, no checks configured in advance. Every guard gets built later, from a specific thing that went wrong, on a date. The evidence sits in this estate's own history: a session-start briefing grew until it killed sessions outright, and the fix was architectural rather than tuning. Building the guard layer during onboarding is the most legible way to fail this course while appearing to take it seriously.

The money, and why the comfortable answer is the dangerous one

Question C at the door has two answers and they fail in opposite directions.

A personal plan is a ceiling. You hit it, work stops, and you find out immediately. That is crude, and it is the case most written material assumes.

The opt-in ceiling

An institutional billing code is a ceiling you have to build yourself. Usage is billed at per-token rates against a department or project. The portal that issues the key does let you set a monthly quota — so a mechanism exists. It is simply not the default state of anything, and nothing in the sign-up path tells you to go and set it.

In this course's own terms: a ceiling you must remember to build is a request that the spender be sensible, and this whole course is about what happens to requests. The fix is one field in a form, which is precisely why it gets skipped.

Set the quota when you create the key, not after the first statement. It is the cheapest guard in this entire document and the only one exempt from the build-nothing-in-advance rule — because it is not a guard you wrote, it is a switch the vendor already shipped.

The free tier has a third shape worth naming, because it is neither: a rate limit. Seventy-five prompts an hour is not a budget, and running into it teaches nothing about what the work costs.

How you would know it worked

Confidence is not the measure. Someone confident after week one has usually skipped the validation. These are observable in the repo.

  • They have re-specced at least once without being prompted to.
  • They can say what the agent did without reading the code — by scope of diff, by files that now exist, by opening the artifact.
  • The repo contains at least one commit recording something that did not work.
  • Their first guard, whenever it appears, points at a specific dated failure.
  • A polished session-start script exists by week two. That is the asymptote, arrived early.
  • The instructions file has grown past a page and is being edited in place of changing the workflow. That is a request being mistaken for a rule.

What is unverified here

This would fail its own course if it presented itself as finished, so:

Nobody has been onboarded this way. Zero runs. The order is derived from what this estate's own retrofits cost it — evidence about what went wrong, not evidence that this sequence prevents it.

The service facts are now first-hand, but not fetched. The site refuses automated requests, so both pages were read as text pasted in by a human on 5 September 2026. Everything in the service table, the two quoted sentences, the 75-prompts-an-hour cap and the list of agent keys comes from that. It is current as of that date and will decay like anything else — the pages moved twice in the seven months before it, once in a way that changed this document's advice.

An earlier draft of this page said the institutional route was uncapped, and that was wrong. It was written from an archived February snapshot plus search summaries, and neither showed the quota field. The portal has offered it all along. The claim was plausible, it survived a read, and it was corrected only because somebody opened the actual page — which is the failure this course is about, committed by the document describing it.

Two things behind these pages remain unread. Whether a newly issued key has any default quota before you set one, and what the per-token rates actually are. Both sit one link further on, and neither has been opened.

No cost figure applies to a beginner doing daily work. The one concrete number in our material describes a capped account in a single 90-minute session, and it was an estimate rather than a measurement. The uncapped case in the caution above has never been measured by anyone here.

The phase labels are dependencies, not durations. "First week" means after the thing below it exists. Nobody has timed any of this.
